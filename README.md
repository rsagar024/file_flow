# FileFlow

Securely sync your workflow anywhere.

FileFlow is a Flutter app for storing, organizing, and sharing files across devices, built on Firebase (Auth, Firestore). Sign-in is phone-number + OTP based, and each account tracks and manages its own logged-in devices.

> **Status**: early-stage. Auth and device/session management are fully built; file browsing, upload, and sharing are UI scaffolding only (no backend wiring yet). See [Current status](#current-status) below, and [`flow.md`](flow.md) / [`design.md`](design.md) for details.

## Current status

**Implemented**
- Phone number + OTP sign-in (Firebase Auth), with auto-verification and resend support
- Account creation with unique email/username validation against Firestore
- Per-account device/session tracking in Firestore, with remote logout of a single device or all other devices
- Bottom-nav dashboard shell (Home / Sharing / Upload / Settings / Profile tabs)

**UI scaffolding only — not wired to real data yet**
- Home screen: file/folder category browsing (All, Folders, Images, Videos, Audios, Documents) — static UI, no Firestore data
- Folder details screen — static UI
- Upload screen — file picker UI present, "Upload File" button has no handler
- "Sharing" and "Settings" dashboard tabs — placeholder text only
- No `firebase_storage` dependency yet, so no actual file storage/sync is implemented despite being the app's end goal

## Tech stack

- **Flutter** (SDK `^3.11.0`), **Dart**
- **Firebase**: `firebase_auth` (phone/OTP), `cloud_firestore`, `firebase_analytics`, `firebase_crashlytics` — project id `file-flow-e29db`
- **State management**: `flutter_bloc`
- **DI**: `get_it`
- **Routing**: `go_router`
- **Functional error handling**: `fpdart` (`Either<Failure, Success>`)
- **Files/media**: `file_picker`, `image_picker`, `cached_network_image`
- **Other**: `flutter_secure_storage`, `connectivity_plus`, `device_info_plus`, `package_info_plus`

## Getting started

### Prerequisites
- Flutter SDK `^3.11.0`
- A Firebase project with **Phone Authentication** and **Firestore** enabled

### Setup
```bash
git clone <repo-url>
cd fileflow
flutter pub get
```

Configure Firebase for your own project:
```bash
flutterfire configure
```
This generates `lib/firebase_options.dart` and the platform config files (`google-services.json` / `GoogleService-Info.plist`). Enable **Phone** sign-in under Firebase Auth and create a Firestore database.

Run the app:
```bash
flutter run
```

### Building
```bash
flutter build apk --release
flutter build appbundle --release
flutter build ios --release
```

## Project structure

```
lib/
├── main.dart                # Firebase init, DI init, MaterialApp.router
├── firebase_options.dart    # generated by flutterfire CLI
├── core/
│   ├── common/              # base widgets, shared widgets, custom painters
│   ├── di/                  # get_it dependency injection container
│   ├── error/                # Failure type
│   ├── resources/           # centralized strings, image paths
│   ├── routes/               # go_router route table
│   ├── services/             # device info, image picker services
│   ├── themes/                # colors, text styles
│   ├── usecase/               # base Usecase/StreamUseCase (Either-returning)
│   └── validator/
└── features/
    ├── auth/          # full clean architecture (data/domain/presentation) — reference implementation
    ├── profile/       # profile + devices screens; reuses auth's domain layer
    ├── home/          # presentation-only (category browsing UI)
    ├── upload/        # presentation-only (upload UI)
    ├── dashboard/     # bottom-nav shell (PageView across the above)
    └── splash/        # initial route, auth-status check
```

See [`design.md`](design.md) for the architecture pattern and data model, and [`flow.md`](flow.md) for screen/navigation flow.

## CI/CD

Two GitHub Actions workflows build and publish releases on PR merge (`.github/workflows/`):
- `flutter-auto-release-dev.yml` — merges to `development` → builds split-ABI release APKs, auto-bumps a patch version with a `-dev` suffix, publishes a GitHub Release
- `flutter-auto-release-master.yml` — merges to `master` → builds APKs + an AAB, bumps the minor version, publishes a GitHub Release

Neither workflow runs tests or `flutter analyze` before merge — there is currently no CI gate on pull requests. See [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Testing

`test/widget_test.dart` is still the default Flutter counter-app smoke test and does not match this app (it expects counter UI that no longer exists) — it will fail if run. Real tests for auth/devices logic don't exist yet; this is a known gap, not something fixed by this documentation update.
